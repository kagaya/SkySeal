# SkySeal macOS Desktop 0.3 — 開発版

Intel Mac と Apple Silicon Mac で、ファイルの保存コピー、ハッシュ、封緘署名、ひまわり画像、時刻証明、履歴をローカルに管理するアプリです。ORCID、気象庁、OpenTimestamps、Bitcoin の公開情報提供元へ直接接続します。通常の封緘に既存の SkySeal サーバーは必要ありません。

## 対応する Mac

| 配布物 | 対象 | 実行環境 |
|---|---|---|
| Intel | Intel プロセッサーの Mac（x86_64） | ネイティブ実行 |
| Apple Silicon | M シリーズのチップを搭載した Mac（arm64） | ネイティブ実行、Rosetta 不要 |

最低対応 OS は macOS 12.3 です。標準の WebKit で、証明書登録の確認ダイアログなどに必要な画面機能が利用できる版を基準にしています。構成する実行ファイルと同梱ライブラリーのアーキテクチャー・最低 OS バージョンもビルド時に検査します。自動起動試験は CI の macOS 15 環境で実行し、macOS 12.3 の実機試験とは区別します。

「この Mac について」に「プロセッサ Intel」とあれば Intel 用、「チップ Apple M…」とあれば Apple Silicon 用を選んでください。利用者による Python、Node.js、Rust、Homebrew の導入は不要です。

## インストール

1. 自分の Mac に対応する配布物をダウンロードします。GitHub Actions の成果物名は `SkySeal-macOS-Intel-development-adhoc` と `SkySeal-macOS-AppleSilicon-development-adhoc` です。
2. DMG を開き、`SkySeal.app` を「アプリケーション」にコピーします。アプリ ZIP を利用する場合は、Finder で展開してから同様にコピーします。
3. コピーした SkySeal を開きます。DMG 内から継続して実行せず、インストールしたアプリを使います。

この版はアドホック署名を施した開発版です。Apple の Developer ID による配布署名と公証は行っていません。開発元の確認に関する警告が表示された場合は、配布元と SHA-256 を確認し、このアプリを開く判断をした場合だけ、macOS の「プライバシーとセキュリティ」に表示される「このまま開く」を使用してください。macOS 12 では「システム環境設定」の「セキュリティとプライバシー」から確認します。組織が管理する Mac では管理者の設定が優先されます。

Apple の案内：[Macでアプリを安全に開く](https://support.apple.com/ja-jp/102445)。アプリ全般の保護を無効化するコマンドは必要ありません。

## 最初の設定

1. ORCID の Public API クライアントを登録し、戻り先を `https://localhost:24731/callback` と完全一致で登録します。アプリの設定欄にクライアント ID を入力します。共通の client secret は使用しません。
2. 設定画面から、この Mac 専用のローカル HTTPS 証明書を作成し、明示操作で信頼登録します。macOS が認証を求めた場合は、その OS の画面で承認します。信頼登録は現在のユーザーの SSL・localhost 用に限定します。
3. 本人登録を開始し、標準ブラウザーで ORCID にログインします。
4. 公開鍵と ORCID の対応を、macOS のキーチェーン認証で承認します。

証明書の信頼登録と封緘時のキーチェーン認証は別の操作です。アプリがパスワードを入力欄で収集・保存することはありません。ローカル HTTPS 受付は認証中だけ起動し、ポート 24731 のループバックアドレスで待ち受けます。

外部サービスへの HTTPS 接続には同梱した公開 CA 証明書を使い、開発用 Python のインストール先に依存しません。ブラウザーの localhost 証明書の信頼とは別に扱います。利用者が `SSL_CERT_FILE` を明示設定した環境では、その追加の信頼設定を尊重します。

## Intel Mac と本人承認

この開発版では、macOS のファイルベースのキーチェーンに P-256 の秘密鍵を置き、秘密鍵で署名するときにキーチェーンのパスワードを要求するアクセス制御を使用します。Touch ID や Secure Enclave を搭載していない Intel Mac も対象です。キーチェーンのパスワードは通常はログインパスワードと同じですが、設定によって異なる場合があります。

Touch ID、iCloud のパスキー同期、Secure Enclave による秘密鍵保護は、この版では実装対象に含めていません。署名ごとの OS 認証を行えるアクセス制御を確認できなければ、封緘を失敗として扱います。

署名の確認画面では、パスワードを入力して「許可」を選びます。「常に許可」を選んで承認を省略できる設定に変わった場合、アプリは以後の署名を拒否します。既存の保存記録は保持されますが、この開発版には鍵の認証ポリシーを修復する画面はありません。

macOS 用には独立した証拠形式を使います。公開証拠から検証できるのは ORCID と公開鍵の結び付き、ファイル集合、電子署名、画像、時刻証明です。キーチェーンのパスワード入力そのものを第三者が独立に検証できる認証器の証明は含みません。検証結果でも、署名の一致と端末側の認証要求を分けて表示します。

Windows の WebAuthn 証拠形式は維持します。デスクトップ版 0.2 以降は Windows・macOS の両形式を検証します。以前配布した Windows 版 0.1 には macOS の新形式の検証処理がないため、macOS の証拠を検証する場合は 0.2 以降が必要です。Mac では新しい本人登録を行い、Windows の資格情報を流用しません。

Linuxの新しい証拠形式はデスクトップ0.3以降で検証できます。0.2はLinux形式に対応していないため、Linuxと相互検証する場合はMac側も0.3以降を使用してください。

## 通常の使い方と保存先

「封緘する」でファイル・フォルダーを選び、アプリ内に保存した実バイト列を確認して封緘します。「履歴」で処理の状態を確認し、時刻証明の再確認と証拠 ZIP の書き出しを行えます。「証拠を検証」で、受け取った証拠と比較対象ファイルを照合できます。

通常のデータ保存先は `~/Library/Application Support/SkySeal` です。元ファイルの保存コピーと履歴はこの場所に保管し、秘密鍵はキーチェーンで管理します。データフォルダーのコピーだけでは秘密鍵を別の Mac に移せません。元の鍵が失われた場合は、過去の証拠を検証できても、新しい封緘には別の本人登録が必要です。

ファイル名や保存パスは公開証拠に含めません。公開証拠が封緘するのは SHA-256 の集合で、同一内容のファイルの個数やフォルダー構造は PC 内の履歴に保持します。署名済みと時刻確認済みは別の状態です。時刻証明の更新は、アプリを開いて「履歴」から再開します。

ORCID の過去の署名鍵が公開されなくなった場合の歴史的な本人登録情報の検証、Bitcoin 全チェーンを自前で検証せず二つの HTTPS 情報提供元を照合する条件など、共通の制約は [デスクトップの詳細説明](README.ja.md) を参照してください。

## 開発者向けビルド

各 CPU のネイティブな Mac で、Xcode Command Line Tools、Python 3.12、Node.js 22、Rust stable を用意し、リポジトリのルートで実行します。

```sh
bash desktop/scripts/build-macos.sh
```

スクリプトは Swift の署名ヘルパー、PyInstaller による同梱エンジン、Tauri のアプリと DMG を作成します。構成するバイナリーの CPU と最低 OS を照合し、アドホック署名を検査します。`.app` の構造・シンボリックリンク・実行権限を維持したアプリ ZIP も作成します。macOS の署名ヘルパーを Windows 配布物へ混入させません。

署名ヘルパーには、旧 Keychain API の認証フラグのバイト順変換に対する互換処理があります。Apple の公開実装を根拠に、変換の前後で実際のパスワード要求ビットを維持する値 `0x0101` を使用し、要求ビットを失った値や未知の権限は拒否します。これは Apple がサポートを表明したフラグの組合せではありません。根拠のソース版をコード内に固定して記載しており、macOS 更新時には保存・再読出し・承認拒否の自動試験と、実際のパスワード画面の受け入れ確認を継続してください。

macOS の一部の標準パス（`/var` など）はシンボリックリンクです。試験は実体パスへ解決した専用の一時保存領域を使います。通常の封緘では、リンクをたどって意図しない場所を含めないため、対象のリンクやコピー中に変化したファイルを拒否します。

## 確認範囲

自動試験では、共通の証拠検証、Windows 形式との互換、macOS の異なる署名形式の混同拒否、TLS 信頼登録の対象制限、同梱エンジンの起動、アプリのウィンドウと画面からエンジンへの初期呼び出しを検査します。Swift の自己診断は一時的な鍵による署名・検証とアクセス制御の構築を確認し、利用者のキーチェーンへ試験用の鍵を追加しません。

CI 専用の別バイナリーでは、隔離した使い捨てのキーチェーンへ鍵を生成し、保存されたアクセス制御を調べ、認証画面を利用できない別プロセスからの署名を拒否することも検査します。この試験の入口は配布用の署名ヘルパーには含めません。

本番 ORCID のブラウザー認証、証明書の信頼登録、実際のキーチェーン認証、取消・パスワード誤入力、更新後の鍵の継続利用は、利用者の Mac での受け入れ試験が必要です。macOS の開発版配布署名は、これらの実機確認の代わりにはなりません。
