# SkySeal Linux Desktop 0.3 — 開発版

Ubuntu上で、保存コピー、ファイルのハッシュ、封緘署名、ひまわり画像、時刻証明、履歴をローカルに管理するアプリです。ORCID、気象庁、OpenTimestamps、Bitcoinの公開情報提供元へ直接接続します。通常の封緘に既存のSkySealサーバーは必要ありません。

## 対応環境と配布物

- Ubuntu 22.04／24.04、Intel・AMDの64ビットCPU（x86_64／amd64）が検証対象です。Linux ARM版は今回の配布物には含みません。
- GNOMEなどのグラフィカルなデスクトップと、既定のWebブラウザーを使います。署名入力はX11またはXWaylandを利用するPinentry GTK2で行います。画面のないSSH接続や、XWaylandのない純粋なWayland環境での入力は対象外です。
- `.deb`はアプリメニューへ登録するインストール用です。`.tar.gz`はフォルダーを展開して起動する配布物です。
- Python、Node.js、Rustの追加導入は不要です。WebKitGTK、GTK、PinentryなどのOS共有ライブラリーは必要で、`.deb`はその依存関係を宣言しています。

この版は署名済みのパッケージリポジトリーから配る正式リリースではなく、ローカルインストールする開発版です。配布ZIPには日本語手順、`BUILD_INFO.json`、`SHA256SUMS.txt`を同梱します。

## インストール

ZIPを展開し、そのフォルダーを端末で開いて実行します。

```sh
sudo apt install ./SkySeal_0.3.1_Linux_x86_64_development.deb
```

アプリメニューから「SkySeal」を開きます。アプリ自体は通常のユーザーで実行します。起動に`sudo`は使いません。既にインストールされていない共有ライブラリーは、通常のUbuntuパッケージ取得としてネットワークから導入されます。

フォルダーから直接使う場合は、必要なOSパッケージを導入してから展開します。

```sh
sudo apt install libwebkit2gtk-4.1-0 pinentry-gtk2 xdg-utils ca-certificates
tar -xzf SkySeal_0.3.1_Linux_x86_64_development.tar.gz
./SkySeal/skyseal-desktop
```

`skyseal-desktop`と`desktop-engine`は同じフォルダーに置いたままにしてください。圧縮ファイルの再梱包や別OS経由のコピーで実行権限を失った場合は、元の配布物からLinux上で展開し直します。他のディストリビューションは同じ依存関係を満たしても未検証です。

## 最初の設定とORCID

1. ORCIDのProduction Public APIクライアントIDを設定します。戻り先は`https://localhost:24731/callback`です。この戻り先を登録済みなら、Windows／Mac版で使用している同じ公開クライアントIDも使えます。共通のclient secretは不要です。
2. 設定画面でローカルHTTPS証明書を用意し、「ブラウザーでHTTPSを確認」を選びます。確認画面にはこのインストール専用の証明書のSHA-256が表示されます。
3. 既定ブラウザーに自分のPCの`https://localhost:24731`が開きます。自己署名証明書の確認が出た場合は、証明書の詳細にあるSHA-256とアプリの表示を照合し、この証明書・接続先に限って通常の許可操作を行います。ブラウザーのTLS検証を全体で無効にする設定や起動オプションは使用しません。
4. ブラウザーに接続確認完了と表示されたらアプリへ戻り、本人登録を開始します。新しいSkySeal専用パスフレーズを2回入力し、ブラウザーでORCIDへログインします。登録内容への署名時に、そのパスフレーズをもう一度入力します。

この接続確認は、今回のブラウザーでこの証明書への接続が成立したことだけを確認します。OS全体の信頼設定や、Firefox・Chromeの証明書データベースを書き換えるものではありません。ブラウザーや証明書の変更、ブラウザーの再起動などで再確認が必要になる場合があります。組織の管理設定などで通常の証明書許可操作ができない場合は、その設定のまま接続確認は完了しません。管理者へこのlocalhost証明書の扱いを確認してください。

HTTPS受付は認証・接続確認の間だけ、IPv4ループバックのポート24731で起動します。同じPCで別の認証操作がこのポートを使用している場合は、先にその操作を終了します。外部HTTPSには同梱した公開CA証明書を使用し、明示された`SSL_CERT_FILE`がある場合はその信頼設定を尊重します。

## Linuxのパスフレーズと鍵

SkySeal専用のパスフレーズを12文字以上で設定します。LinuxのログインパスワードやORCIDのパスワードとは別のものです。複数の単語など、長く推測されにくいものを選んでください。

入力はOSパッケージの`/usr/bin/pinentry-gtk-2`による別ウィンドウで行います。アプリのWeb画面、プロセス引数、環境変数、ログへパスフレーズを渡さず、gpg-agentやパスワードキャッシュも利用しません。署名のたびに新しい入力画面を開き、誤入力や取消では署名を返しません。

P-256秘密鍵は、ScryptとAES-256-GCMで暗号化したPKCS8として保存します。鍵フォルダーは所有者のみ、鍵ファイルは所有者の読み書きのみとし、リンクや不適切な権限、鍵・メタデータの改変を拒否します。これはソフトウェアによる保護です。パスフレーズを知る人は鍵を復号・移行でき、ハードウェアによる非抽出性を保証しません。署名中はエンジンのメモリーに復号鍵が存在し、Pythonによる一時コピーを含む完全なメモリー消去も保証しません。

**パスフレーズを忘れた場合、ORCIDへの再ログインやLinuxのログインパスワードでは元の鍵を回復できません。** この開発版にパスフレーズ再設定・鍵の更新画面はありません。過去の証拠は公開鍵で検証できますが、新しい署名には別の本人登録が必要です。

Linuxの公開証拠が検証するのは、ORCIDと公開鍵の結び付き、ファイル集合、電子署名、画像、時刻証明です。パスフレーズ入力や端末内の鍵保護そのものを第三者へ独立に証明する形式ではありません。検証結果でも暗号署名の一致と本人承認の保証範囲を分けて表示します。

## 保存先・バックアップ・互換性

通常の保存先は`~/.local/share/SkySeal`です。絶対パスの`XDG_DATA_HOME`を設定している場合は、その下の`SkySeal`を使います。暗号化鍵は`keys/skyseal-key-….json`にあり、保存コピー・履歴・本人登録情報とともに保管します。バックアップにはデータフォルダー全体と、別に管理したパスフレーズの両方が必要です。復元時も所有者とアクセス権を維持してください。

「封緘する」で保存コピーを作り、内容を確認して署名します。「履歴」から時刻証明の再確認と証拠ZIPの書き出し、「証拠を検証」から候補ファイルの照合ができます。公開証拠ZIPに元ファイルや非公開パス、暗号化秘密鍵は含めません。

デスクトップ0.3以降はWindows・macOS・Linuxの3形式を検証します。以前の0.1／0.2は新しいLinux形式を検証できないため、Linuxの証拠を検証する端末には0.3以降が必要です。Windows／Macでの本人登録をLinuxの署名鍵として流用せず、Linuxでは新しく本人登録します。

公開証拠が封緘するのはSHA-256の集合で、同一内容の個数やフォルダー構造はローカル履歴に保持します。署名済みと時刻確認済みは別です。ORCIDの過去の公開署名鍵やBitcoin情報提供元など、共通の制約は[デスクトップの詳細説明](README.ja.md)を参照してください。

## ビルドと確認範囲

Ubuntu 22.04 x86_64で、ビルド依存関係、Python 3.12、Node.js 22、Rustを用意し、リポジトリーのルートで実行します。依存パッケージの一覧は`.github/workflows/desktop-linux.yml`にあります。

```sh
bash desktop/scripts/build-linux.sh
```

CIでは証拠の互換性・改変拒否に加え、使い捨ての鍵と試験専用パスフレーズで実際のPinentry画面を操作し、正しい署名、誤入力、取消、再署名時の新しい入力要求を確認します。パッケージのELF・glibc要求を監査し、配布する`.deb`をUbuntu 22.04／24.04へインストールして、通常ユーザー・WebKitのサンドボックス有効のままGUIと同梱エンジンを起動します。試験用の秘密情報を注入する入口は配布用エンジンへ追加しません。

実際のFirefox／Chromeでの証明書許可と本番ORCIDログインから封緘までの通し操作は、利用者の環境での受け入れ確認が必要です。各ビルドの結果・制約は同梱の`BUILD_INFO.json`とGitHub Actionsの診断結果を参照してください。
